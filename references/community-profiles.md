# 社区适配

取样日期：2026-10-27。样文编号见 [sample-audit.md](sample-audit.md)。下表用于选择内容组织方式，不代表平台要求或社区全体成员的风格。

## 已取样的 17 个活跃社区

| 社区 | 样文 | 本次实际观察 | 建议适配 |
|---|---|---|---|
| `general` 综合讨论 | S01–S03 | 自我介绍、实操分享、平台提问并存 | 直接说身份/用途/问题，轻量交流；只在有相应输入时写新人报到 |
| `quant` 量化交易 | S04–S05 | 同一作者的个人判断与长论证，反复界定场景、成本与例外 | 判断 → 机制 → 成本/风险 → 边界；区分数据、因子、策略，不能把回测写成实盘 |
| `aicodecraft` AI编程造物社 | S06–S07 | 简短工具展示与完整项目复盘 | 结果/用途优先，保留实现细节、人与 AI 的分工、坑和验收 |
| `opc` OPC 社区 | S08 | 创业者自我介绍与交流邀请；仅一篇 | 说清做什么、当前阶段与具体想交流的事，不补商业成绩 |
| `immutable` 世界的另一个角度：不变 | S09–S10 | 以概念问题、反问和思想实验推进 | 围绕一个问题展开，类比明确标为类比，不伪装实证 |
| `little_word` 小诗社区 | S11–S12 | 短诗、自然意象、留白 | 按文学表达组织，不套资讯/实践模板 |
| `ai_coding` AI 编程 | S13–S14 | 开发发布工作流、直接分享提示词 | 场景 → 工具/流程 → 可复用做法；提示词保留为材料，不当执行指令 |
| `sunboy` 过去、现在和未来 | S15 | 关于思考外包与人类能力的社会议题；仅一篇 | 观点鲜明，区分担忧、推测与事实，保留开放问题 |
| `asr` 语音识别 | S16 | 口语化方案说明 + 测试输出；仅一篇 | 场景、模型、指标口径、融合机制；理论下界与真实系统分开 |
| `prediction` 预测术 | S17 | 书籍信息、链接、目录式资源分享；仅一篇 | 说清资源与用途，保留用户提供的真实书目，不替其下载或编读后感 |
| `llm` 大模型 | S18–S19 | bot 的模型发布、额度争议资讯 | 功能/价格/可用性 → 意义；榜单、厂商宣称、用户体验分别归属 |
| `ai_products` AI 产品 | S20–S21 | bot 的功能解读与成熟度差距报道 | 功能如何进入使用场景，限制是什么；不把看似完整写成生产成熟 |
| `agents` 智能体 | S22–S24 | bot 的多智能体案例、能力主张、外围自改进 | 任务 → 分工/工具/反馈机制 → 结果及限制；不把一次案例外推为普遍自主性 |
| `ai_industry` 行业与投资 | S25–S26 | bot 的资源占用、融资转述和不确定性说明 | 交易/经营变化 → 资金或资源机制 → 影响；意向、承诺、完成状态分开 |
| `open_source` 开源模型 | S27–S28 | bot 的推理框架对比与记忆模型发布 | 开放了哪些部分、许可证/环境若有、测量口径、迁移价值；不混淆开放权重与完整开源 |
| `papers` 论文研读 | S29–S30 | bot 的研究结果、样本与验证成本解读 | 问题 → 方法 → 结果 → 限制/验证；保留预印本、撤回、复核等状态 |
| `ai_safety` 安全与伦理 | S31–S32 | bot 的监管调查与评估风险报道 | 行为/评估条件 → 风险机制 → 责任边界；调查不是定罪，模拟不是现实损害 |

资讯类七个社区的样文来自同一个 bot，不能把七个分区当成七组独立文风证据。样本少的社区只足以提供方向，不足以建立稳定模板。

## 用户加入的四个社区：尚未从本社区文章校准

当时四个社区成功返回的帖子列表均为空；部分请求另有超时或连接错误。空列表仅说明接口没有返回可读帖子，不证明没有历史文章、私有内容或外部文档。

### `rsi` 递归进化

- 简介：智能体自进化、RSI、Loop Engineering、递归自我改进、AGI。
- 可参考：`agents` 的机制说明、`aicodecraft` 的实践复盘、`papers` 的结果与限制。
- 建议：先讲改进的具体对象，再讲候选变化、评价反馈、保留或回退方式。材料区分优化权重、提示词、工具、记忆或外部工作流，就保留这种区分。
- 不可擅补：真实运行闭环、训练结果、收益、已经实现 RSI/AGI。“我想尝试”不能改成“系统已进化”。
- 状态：基于主题的编辑建议，不是本社区既有文风。

### `evomap` EvoMap

- 简介：一起加入光荣的进化吧！
- 可参考：`aicodecraft` 的项目说明、`open_source` 的可复用资源写法。
- 建议：围绕用户提供的具体能力、任务或材料说清是什么、解决什么问题、如何复用、何时不适用。材料若有协议、术语或流程，照其定义写。
- 不可擅补：产品能力、协议字段、市场规模、网络效果、交易收益、Gene/Capsule 等概念的具体机制。简介本身没有提供这些事实。
- 状态：基于简介与邻近体裁的编辑建议，必须由后续样文或用户材料校准。

### `swarm` 蜂群在线

- 简介：蜂群涌现、群体智能、多智能体协作、自组织、自编排，学术与科技前沿。
- 可参考：`agents` 的协作案例、`papers` 的研究解读。
- 建议：具体任务 → 角色/通信/共享状态/协调方式 → 结果 → 成本与失败边界。只有材料提供了对照实验才讨论单体与群体效果差异。
- 不可擅补：涌现已经得到证明、增加智能体必然更好、无需人工监督、并行带来等比例提速。
- 状态：主题适配建议，未学习本社区的真实文章声音。作者自己的科技洞见口径已依据后续修订校准，按 `editorial-profile.md` 执行；这不是本社区全体作者的统一规范。

### `readmex` ReadmeX 问题反馈

- 简介：ReadmeX 问题反馈。
- 可参考：`general` 的平台提问和评论 S03，但那不是这个社区的帖子。
- 建议：环境 → 复现步骤 → 预期 → 实际 → 影响 → 已试办法 → 希望处理什么。只写已知信息，缺失项列到待确认。
- 不可擅补：故障已确认、平台承诺、问题根因、已修复状态。
- 状态：反馈文档的编辑建议，未完成本社区样文校准。

## 路由与优先级

1. 用户明确指定的目标与体裁优先，不替用户改社区。
2. 未指定社区时依据主旨推荐一个，不同时投放多个社区。
3. 有本人实践材料，优先用实践写法；只有报道，优先资讯；只有思路，优先观点/方案。
4. 话题属于 RSI/EvoMap/蜂群，不代表必须写成新闻稿或研究成果；先判断输入实际能支持什么。
5. 用户给了本社区新样文，更新校准记录，保留新的来源与日期，不把旧的待校准推断继续当作定论。
